## 背景一句话

第一阶段（当前页依据、证据边界、评测基线）已上线（见 `04-开发进度记录.md` 续十一至续十九）。本轮给"外部事实/时效性问题"接一条新的证据链，跟"书内依据""用户记忆"（未实现，不属于本轮）并列。

## 技术选型（已定，不用再讨论）

- 调用千问要走 **DashScope 原生接口**（`POST .../services/aigc/text-generation/generation`），**不能走 OpenAI 兼容接口**——后者拿不到结构化来源列表。
- 请求参数：`parameters.enable_search: true`，`parameters.search_options: {enable_source: true, enable_citation: true}`。
- 响应里 `output.search_info.search_results` 是逐条来源（url/title/site_name），`output.choices[0].message.content` 里模型自己给的答案会带 `[数字]` 引用编号——**这段千问自己写的答案只作为参考素材，不直接展示给用户**，最终回答仍要走 ChatBook 现有的 DeepSeek 主模型组织语言（呼应 `14` 号文档"不是换模型"那条澄清）。

## 具体任务

### T1：后端新增外部查证调用模块
- 封装对千问 DashScope 原生接口的调用：输入问题，输出"是否成功 + 若干条来源（url/title/site_name）+ 千问给的参考文本"。
- 超时（建议几秒级，具体数值自己测出来定）、异常、空结果都要优雅降级——单个外部调用失败不能拖垮整个回答，这是 `CLAUDE.md` 已有的硬约束（`Promise.allSettled` 精神），Python 侧做等价处理。
- API Key 从环境变量读（比如 `DASHSCOPE_API_KEY`），参考现有 `DEEPSEEK_API_KEY` 的处理方式，不硬编码。**生产用的 Key 需要新建一个描述清楚的正式 Key，不要沿用产品负责人测试时建的那个临时 Key**（那个描述里写了"临时,测完可删"）。

### T2：证据组装与来源标注
- 新增一份**域名信任名单**（政府网站、官方机构、权威媒体、主流百科等），对千问返回的每条来源按域名匹配打标（比如"较可信"/"来源未知"），纯代码规则，不额外调用 AI 判断。
- 外部查证结果作为独立的【外部查证】标签块拼进现有 `context_block`，和书内正文分开，不要混进同一段。
- 提示词补一条规则：用到外部查证内容时，必须让读者能分辨"这句话是书里的"还是"这句是查来的"；多个来源有分歧时要如实呈现分歧，不能自己选一边当定论。
- 完成事件的证据元数据（现有 `availableEvidenceType`）新增一个值表示"本次用到了外部查证"，具体命名自己定。**延续第一阶段已经定下的语义边界：这个字段只表示"用了什么材料"，不表示"已经被核实为真"**，别踩 `f59eb25` 那次改过的坑。

### T3：触发逻辑
- 提示词层面：书内内容问题、文学开放讨论不触发外部查证；现实事实/时效性/高风险领域问题可以触发。
- 建议先用"提示词指导 + 模型自己判断要不要触发"这个轻量方案；如果测试发现不可靠（该触发的没触发，或乱触发），再考虑加一层独立判断逻辑，不要一开始就上复杂方案。
- **政治类内容本轮建议直接不自动触发**（`14`号文档已提议，需产品负责人最终确认，见下方"待确认"）。

### T4：前端展示
- 完成事件带外部查证来源时，前端渲染成答案下方一个可折叠"查看来源"条：标题 + 域名 + 日期，不影响正文阅读体验，不破坏现有"不用 Markdown"的格式约束。
- 听书场景：TTS 不朗读来源链接，只在文字记录/对话历史里保留。

### T5：降级
- 千问调用失败/超时/空结果：直接不使用外部查证，走已有的"依据不足要老实说"规则，不能让用户卡住等待，也不能假装查到了。

### T6：评测集扩展（可以现在就开工，不依赖 T1～T5）
- 在 `api/evals/ai_quality/cases.jsonl` 新增"外部事实/时效性"这一类题，可以直接改造产品负责人这次实测过的 5 道真实问题（达利欧近况、桥水规模、老子真实性、清崎近况——原始数据在决策层本地，需要时可以要）。覆盖：有稳定来源可查、来源冲突、查不到/需要降级三种情形。
- 评分表新增或扩展一项"引用有效性"（来源是不是真的支撑了给出的结论），沿用现有 0/1/2 打分制。

## 验收标准

1. 未触发联网的问题（书内内容/文学讨论）行为不回归。
2. 触发联网时，用户能看到带来源的回答，来源可展开查看。
3. 千问调用失败时优雅降级，不阻塞回答、不假装有联网结果。
4. 高风险问题即使有外部查证结果，仍然遵守已有的确定性安全前缀规则，不被外部查证结果绕过。
5. 固定题集能跑通，dry-run 通过；真实调用需要显式开启，且要产品负责人批准后才能用真实付费 Key 跑。
6. 后端完整单测、既有回归测试（阅读上下文/苏格拉底/听书相关）全部通过。
7. 没有真机验证的部分要明确标注，不能写成已完成。
