## 1. 背景与目标

- 用户要求 **2026-09-30 之前**产品能正式公开测试（安卓和 iOS 至少一端）。
- 平台策略（已定）：**安卓做国内公开测试主力**（无审核、国内可连腾讯云）；**iOS 同步提交 TestFlight 外部测试审核**（当前只连 Railway，国内 iOS 用户暂连不上，先服务海外/身边用户）。
- 本任务卡范围：**阅读器体验升级**，要求 **iOS 和安卓两端都好用**。听书页、AI 引导式对话、阅读沉淀是后续任务卡，**本卡不做**。

## 2. 用户已拍板的决策（不要改）

1. 阅读时**沉浸式**：不再有顶部栏、底部栏占位；正文占满可用空间。
2. **工具栏呼出/收起**：点屏幕中间 **或** 从屏幕中部下滑呼出；上滑或点正文收起。
3. 工具栏样式：**低饱和暖棕玻璃**，**透明度 75%**（细节见 §4.2）。
4. 收起后，**原工具栏位置不留空白**；工具栏是浮层，呼出/收起时**正文不重排、不跳动**。
5. 收起状态底部有一条常驻信息条：**左：当前时间 + 小电池（带电量数字）；中：当前章节名（不显示书名）；右：百分比进度（不显示页数）**。
6. 工具栏内：**进度可拖动**；**字号改为滑块**（最左最小、最右最大，取代原来的加号/减号）；**字体切换**（宋体/黑体/楷体）；**主题三档**（护眼/默认/晚间，现有能力沿用）。
7. **翻页动画本卡不作为交付**（仅做 §4.3 技术验证）。
8. 安卓字体现在选不了（宋/黑/楷显示一样）→ **必须修好**。
9. 为测试而做的功能（字体诊断、样例字体等）**最终要对用户隐藏**（§4.4）。

## 3. 任务顺序（有先后依赖，请按序）

### 3.1 【最先】安卓字体修复（含体积优化）
- 现象：安卓阅读器无法切换宋体/黑体/楷体，三者显示相同。
- 我们已知的代码事实（`mobile/screens/ReaderScreen.js`）：标准阅读模式每翻一页都会重新加载一个 WebView；字体是以 **base64 内联**方式塞进每页 HTML 的 `@font-face`。字体文件很大：`LXGWWenKai-Regular.ttf` 25MB、`SourceHanSerifSC-Regular.ttf` 15MB、`SourceHanSansSC-Regular.ttf` 11MB（另有 Bold 版本）。代码注释也写了"加载失败会静默回退到默认字体"。
- **决策层的假设（未验证，请你先验证再动手）**：字体过大导致在安卓 WebView 里加载失败/超时，静默回退成默认字体；同时可能拖慢翻页。
- 步骤：**先用现有的"字体诊断"确认真实原因**，再修。**注意：不要在字体修好之前把字体诊断隐藏/删除**。
- 修复方向（可自行选更好的，但要汇报理由）：① 字体**子集化**（保留常用汉字+标点+常见繁体，目标每个几 MB）；② 改为从**本地文件 URI 加载**，不再 base64 内联到每页 HTML；③ 子集外的生僻字回退到系统字体，**请记录回退策略**。保留字体许可证文件（OFL）。
- 验收见 `05-验收标准.md` 对应条目。

### 3.2 沉浸式布局 + 玻璃工具栏（两端）
以 `docs/设计稿/ChatBook阅读器沉浸式样板.html` 为**唯一依据**，读源码里的实际数值，不要凭描述重新诠释。

**布局**
- 移除现有顶部栏/底部栏对正文的占位；正文区上边只留刘海/安全区，下边只留底部信息条（约 44px 高）。
- 隐藏系统状态栏（时间/电量由底部信息条自己显示）。iOS 刘海区域的安全区仍需保留。
- 底部信息条：左 时间(HH:MM，跟随手机系统)+电池图标+电量数字；中 章节名（过长省略号）；右 百分比。工具栏呼出时信息条淡出。

**玻璃工具栏（顶部条 + 底部面板）**
- 底色 `rgba(103,84,66,0.75)`，白色文字，与正文交界处 1px 白色 22% 透明分隔线，背景模糊 blur 14（见 §5 关于模糊的说明）。
- 顶部条：返回、书名（此处可显示书名）、目录。底部面板（自上而下）：阅读进度滑块+百分比；字号滑块（12–28，步长 1，左小 A 右大 A，右侧显示数值）；字体三选一（宋体/黑体/楷体，按钮文字用各自字体渲染）；主题三档。
- 浮层出现/消失动画 ≈250ms，尊重系统"减少动态效果"设置。

**手势规则（必须实现，保证不与选字冲突）**
1. 下滑呼出的判定：竖向位移 ≥ 60px 且 竖向 > 2× 横向。上滑收起同理。
2. **正在选字或长按（≥350ms）触发后，不识别下滑/上滑**，直到选区取消。
3. **手势起点在屏幕顶部边缘约 24px 内时，不响应下滑**（避开系统通知栏下拉）。
4. 点屏幕中间 30%–70% 区域呼出；工具栏展开时点正文收起；点左右两侧不属于本卡（翻页保持现有手势）。
5. 与现有翻页手势、选字气泡（划线/问AI）、右下角悬浮球（问AI）并存——**样板没有画出这些现有元素，它们保持现有行为**；若位置与底部信息条冲突，你调整后**汇报并附截图**。

### 3.3 翻页动画技术验证（限时半天到一天，不是交付项）
- 目标：验证能否做"仿真卷页"翻页。候选：开源库 StPageFlip（MIT，原项目不再维护，有 gul-labs 的更新分支）放进标准阅读的 WebView 里。
- 只回答三个问题：① 真机（安卓、iPhone 各一台）是否流畅；② **选字/划线是否不受影响**（翻页库会接管拖动手势，是最大风险）；③ 换字体/字号/主题后是否正常。
- **无论通过与否，都不得影响 §3.1、§3.2 的交付**。汇报结论；是否采用由决策层+用户定。备选：平移、覆盖、无动画。

### 3.4 【最后】隐藏测试功能
- 字体诊断、样例字体，以及"我的"页的"AEC技术验证（内部）"等仅测试用的入口：对普通用户隐藏。
- 做法建议：复用"我的"页**连点标题 7 下**的隐藏入口机制（见 `mobile/screens/ProfileScreen.js` 的 `DevServerSwitch`/`useDevMenu`），把这些入口收进去；或用 `__DEV__` 门控。**请先列一份"将被隐藏的功能清单"汇报**，不要静默删除功能。

## 4. 两端与原版模式

- 阅读器目前有"原版（epub.js）"和"标准"两种渲染方式。**沉浸式先做在"标准"模式**。请你**先评估并汇报**：iOS/安卓各自默认走哪种？原版模式是否也要套同一层沉浸壳、工作量多大？**不要自行砍掉原版模式**，由决策层拍板。

## 5. 原生模块与打包（非常重要）

- 底部电量需要 `expo-battery`，玻璃模糊需要 `expo-blur`。**两者当前都没有安装**（已核对 `mobile/package.json`），都是**原生模块**，**不能通过 OTA 更新加到已发布的包里**，必须**重新打包**。
- **⚠️ 崩溃风险**：运行时版本目前是 `1.0.0`。如果把 import 了新原生模块的 JS 用 OTA 推给旧安装包，**旧包会直接崩溃**。因此：使用新原生模块的代码，必须换一个新的 runtimeVersion（或用等价的隔离方式），只发给新包。**请在动手前先汇报你的隔离方案。**
- 安卓：`expo-blur` 在安卓上可能只能做到半透明、做不到真模糊（未验证）。请实测；做好**"只靠半透明也好看"的降级**，不要为了模糊效果牺牲可读性。
- 打包与提交计划请提前汇报：安卓 preview APK；**iOS TestFlight 构建尽早（建议 9/25 前）提交外部测试审核**（需要用户的 Apple 账号操作时，提前告诉用户）。
- 服务器：本次不改后端，不动 `extension/`。

## 6. 汇报与验收方式

- 每完成一个 §3 子项，在 `04-开发进度记录.md` 追加一条：**做了什么 / 怎么验证的（真机还是非真机）/ 哪些没验证 / 遗留问题**，标题加平台标签 `[Android]/[iOS]/[共用]`。
- 第一版能跑后，把**真机截图（收起态、呼出态、深/浅主题各一）**发给决策层对照样板核对，**不要默认照做=做对**。

- 满足 `05-验收标准.md` 的通用完成定义（真机验证、写进进度记录、不破坏旧接口等）。
