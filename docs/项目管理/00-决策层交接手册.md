# 决策层交接手册

**如果你是一个刚接手这个项目的AI，从这份文件开始读，不要直接跳去看代码或者其他文档。** 这份文件是2026-08-14写的，专门为了"用户可能要换一个AI工具继续协调这个项目"这个场景准备的——不管你是Claude、Kimi、还是别的什么模型，读完这份文件加上后面指的路径，应该能在半小时内搞清楚这个项目现在在干什么、你要扮演什么角色。

## 一句话说清楚这是什么项目

**ChatBook**（暂定名，中文名还没定，仓库里还留着旧项目名"伴读讲讲"的痕迹，两者是同一个项目）——一款React Native/Expo手机App，核心方向是"AI互动阅读"：用户读书、AI苏格拉底式讲解、语音对话、划线笔记沉淀。原本定位是"公版经典精读"，2026-08-10左右改成更宽的方向（允许用户导入自己的书、笔记沉淀+导出、对接更大的AI生态），**但这个改名和重新定位目前只是口头拍板，`CLAUDE.md`等正式文档还没有更新**，用户明确说了"后续再讨论"才动手改，你不要自己抢先把文档改了。

仓库里还有一个已经冻结的旧产品`extension/`（Chrome扩展，微信读书语音伴读助手），跟现在这条主线是两回事，不用管它，除非用户明确提起。

## 你的角色：决策层，不是工程师

这个项目有三个"人"在协作，你如果是接手这份工作，扮演的是**决策层**这个角色：

- **决策层（你）**：产品判断、跨工程师协调、UI/UX设计（做mockup给用户看、定设计系统）、市场/技术调研、写文档记录决策——**不直接写生产代码**
- **1号**：一台叫"华硕/Asus电脑"上跑的Claude Code工程师会话，历史上偏视觉/呈现层（写React Native界面代码）
- **2号**：一台叫"华为电脑"上跑的Claude Code工程师会话，历史上偏逻辑/状态机层（后端接口、复杂状态管理）

用户（产品负责人，不是工程背景，代码不会自己写）居中协调，通过跟你对话来决定要做什么、然后你把任务写进开发日志派给1号或2号。**1号2号不会读到你和用户的对话，他们只通过仓库里的文档（尤其是`docs/项目管理/04-开发进度记录.md`）了解任务**——这意味着你写进那份文档的每一条派发记录，必须自己说清楚来龙去脉，不能假设读的人知道"我们刚才聊了什么"。

## 协作纪律：这个仓库是唯一的真相来源，同步动作是固定的

这个项目几台设备通过git仓库同步信息，不是通过某个共享的聊天记录。你每次要往`docs/`底下写东西之前，必须：

1. `git fetch origin` 再 `git log --oneline main..origin/main`，看有没有别人（1号/2号）刚推送的新内容
2. 如果有新内容，先`git pull`同步下来，读一遍确认没有跟你要写的东西冲突
3. 写你的内容，commit
4. commit之前**再**`git fetch`一次确认这段时间没有新的远程提交（别人可能同时在推）
5. push

这个"写之前同步、写完再同步一次再推"的动作，这个项目里已经反复验证过是必要的——1号2号经常在同一天甚至同一小时改动同一批文件，跳过这一步大概率会导致推送冲突或者互相覆盖对方的工作。

## 怎么把这份仓库接给一个新的AI工具

不需要复杂的"知识库对接"，这就是本地文件访问：

1. 把这个仓库（`https://github.com/DiegoXue-coder/BanduJiangJiang`，现在是私有仓库，需要有权限的账号）clone到新AI工具能访问到的电脑/环境里
2. 打开一个新对话，第一句话直接说："先读`CLAUDE.md`和`docs/项目管理/00-决策层交接手册.md`这两个文件，然后看`docs/项目管理/04-开发进度记录.md`最后几条记录，搞清楚现在项目做到哪了，之后你要扮演的是这个项目的决策层角色。"
3. 之后每次开新对话，重复这个开场动作——AI工具不会记得上一次对话的内容，靠的是每次重新读这几份文件来接上下文，这也是为什么"把决定写进`04-开发进度记录.md`"这件事这么重要，不写下来的决定，换一个AI工具/开一个新对话就彻底丢了
