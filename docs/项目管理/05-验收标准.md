# 验收标准（Acceptance Criteria / Definition of Done）

> 背景：2026-07-14 用户在阶段四真机测试时发现整个项目从未定义过"做到什么程度算通过"，
> WBS 只写了任务范围没写验收门槛（规划层的真实疏漏，已如实留档）。自阶段四起，
> **每个阶段开工前必须先在本文档定好验收标准，缺标准不开工。**
> 阶段一到三已事实性收尾，经用户确认不回溯补写。

## 通用完成定义（Definition of Done）——适用于每一次交付，与具体阶段无关

任何功能或修复，**同时满足**以下各条才算"完成"（阶段验收标准是在这个底线之上叠加的）：

1. 真机验证过，不是只在 web 端/本地跑通（对应经验法则第6条"验证分层如实汇报"）
2. 代码已推送且 Railway 自动部署成功、`/health` 正常（本项目合并即上线）
3. 改动已写进开发进度记录（做了什么、为什么这么做）
4. 对 `node_modules` 的任何修改有 patch-package 补丁持久化
5. 不破坏 `extension/` 依赖的旧接口和旧表结构（"只加不改"原则）
6. 对照当前阶段验收标准自检过，汇报时说明哪些项已自测通过、哪些需要用户验证

> 颗粒度说明：质量管理按三层设计——本 DoD 是全局底线（一次定义处处生效）；
> 阶段验收标准只给交付物定（下方各节）；任务级质量不写文档，未来靠自动化测试实现
> （单人+小代码量阶段人工验收够用，代码量增长或引入协作者时再补后端 API 自动化测试，已记入规划）。

## 阶段四：AI 对话 + 语音

### 功能验收（全部必须在真机上验证，web 端不算数）

1. **上下文相关性**：长按选字→"问AI"，AI 回答必须紧扣所选文字和这本书的内容（不是脱离原文的泛泛而谈）——《道德经》《论语》各抽查 3 处不同段落验证
2. **两种回应模式都要**（2026-07-14 用户拍板）：直接讲解模式 + 苏格拉底提问模式，用户可切换；复用插件版已验证的 style 参数提示词，苏格拉底模式必须"先提问引导，不直接给答案"
3. **对话串 UI**：多轮对话堆叠可滚动，AI/用户气泡视觉区分，追问时上下文连贯（AI 记得前几轮说过什么）
4. **TTS 播放 + 手动打断**：回答可语音播放；停止按钮点击后**即刻静音**（这是"级联式+手动打断"架构决策的最终落地验收点）
5. **STT 语音输入**：麦克风按钮录音→转文字→正常发送提问
6. **数据飞轮第一环**：每次问答写入 `qa_history` 且带 embedding（用数据库查询核对，不只看界面）；划线时的 embedding 计算已在阶段三实现，此处验证问答侧
7. **RAG 上下文注入**：提问时向量检索历史相关问答/划线并注入 prompt（按 WBS 阶段四范围）

### 质量门槛（2026-07-14 用户拍板）

- **响应速度**：非流式返回 + 等待期间显示加载动画，从发送到完整显示 **10 秒内**为通过；流式输出明确排除在 v1 之外，留作后续优化
- **回答长度**：沿用插件版 System Prompt 的字数约束（TTS 朗读时长合理）

### 健壮性

- 断网 / 后端不可用时有明确报错提示，**不允许无提示卡死**（阶段三选区菜单 bug 的同类问题引以为戒）
- AI 接口调用失败不影响划线、阅读等其他功能继续使用（Promise.allSettled 原则）

### 阻塞项（验收前必须先修复）

- **选区手柄拖动 bug**：长按选字后拖动手柄调整范围，操作菜单消失且不再出现——用户无法精确划选想问的文字，直接阻塞"问AI"核心流程，此 bug 不修复阶段四不能验收

## 阶段五：划线复盘页面

> 2026-07-17 草拟并经用户拍板确认，正式生效。

### 功能验收

1. **跨书聚合列表**：一个列表里混排展示用户在所有书里的划线（`highlights`）和问答记录（`qa_history`），不分书本 tab，按时间倒序（最新的在最上面）

### 质量门槛

### 健壮性

- 加载失败（断网/接口报错）要有明确提示 + 重试入口，不能无提示卡死（跟阶段四同样的门槛）

## 阶段十一：图标/交互细节修正 + 字号字体功能（2026-07-2X）

### 功能验收

1. **阅读器头部导航方案定案（推翻阶段十讨论中的汉堡菜单方案）**：不做侧边栏收纳，恢复头部平铺图标，四个功能：字号调节（新增）、选择章节、问AI（不需要先选字的直接入口，保留）、颜色/主题调节。图标用 Tabler Icons（MIT协议，免费商用）：字号 `ti-text-size`、目录 `ti-list`、问AI `ti-message-circle`、颜色 `ti-brightness`。是否搭配文字标签（"目录""AI""颜色"）由实现后观感决定，图标不够直观的加文字
2. **底部三个 tab 图标**：书架 `ti-books`、划线复盘 `ti-highlight`、我的 `ti-user-circle`，颜色统一用阶段十定的主强调色 `#8C5642`
3. **字号调节功能**（新增）：阅读器内可调节正文字号大小
4. **颜色/主题调节改版**：三档横向滑动切换（默认 / 护眼模式 / 晚间阅读模式），不做二级菜单，直接在触发后的控件里三选一
5. **全局字体替换**：正文用思源宋体（衬线体），界面元素用思源黑体（无衬线体），均为 Adobe+Google 联合开发、SIL 开源协议，免费商用无版权风险，不需要额外授权或标注

### 需要修复的 bug

6. **章节目录无法返回**：打开目录后左滑手势失效，退不出去，需要排查修复
7. **划线选字成功率因书而异，需要专项排查**：用户实测发现《中庸》比《大学》明显更容易选字失败——此前判断"这是`epub.js`库层面的通病、跟内容无关"可能不完整，需要专项对比这两本书实际渲染出来的 HTML/DOM 结构差异（两本都是从维基文库按自然段落切分导入的，需要查是否是段落粒度/排版结构导致的差异），不能直接套用之前"无解"的结论——如果确认是内容/排版层面的具体原因，可能有比"迁移Readium"成本低得多的修复方式

### 明确不在本阶段范围内

- 迁移到 Readium 原生渲染引擎（记入 `06-未来开发清单.md`，只有在上条排查结果证明是纯库层面通病、且用户反馈量确实很大时才考虑启动，是一次大工程，不能顺带做）
- 书本封面插画（沿用阶段十的结论，独立后续任务）

### 健壮性

- 沿用既有门槛：不允许因为本阶段改动导致任何现有功能不可用或白屏
- 字体替换后需要确认所有语言/标点（含苏格拉底模式常出现的书名号「」、引号）渲染正常，没有缺字/方框字符

## 阶段十二：知识图谱 v1（2026-07-26 决策层用可视化工具做了完整交互探索后定稿）

> 范围来自 `06-未来开发清单.md`"知识图谱式关联呈现"条目，但本阶段**明确只做其中定型的部分**，
> 不要把该条目里记的"进阶方向"（技能树解锁、链接预测推荐、用户理解方式提取、文言文词汇追踪）
> 当成本阶段范围默认展开——那些都还没设计定型，混进来会导致范围失控。

### 前置内容任务（跟App功能开发并行，非本阶段核心）

- **《中庸》EPUB重新生成并替换生产库**：阶段十一已经修复了章节切分过短的问题（`MIN_CHAPTER_CHARS=150`+合并短段落），但还没重新生成`zhongyong_clean.epub`并导入替换现有版本。当前账号是纯测试环境，没有需要保护的真实用户数据，直接执行替换即可，不需要额外的迁移/兼容方案

### 功能验收

1. **概念提取**：每条 `highlights`/`qa_history` 记录，用DeepSeek提炼1-3个核心概念词，同时生成一句话说明"这段内容为什么算这个概念"（供后续详情弹窗使用，不是额外调用，同一次生成里一起产出）
2. **概念去重合并**：对提取出的概念关键词做向量相似度聚类，说法不同但意思相近的合并成一个canonical节点；一个节点可以、也应该能同时装着来自不同书的内容（这是核心设计要求，不是"一个节点一本书"）
3. **概念节点间的关联**：复用现有关联检测机制（embedding相似度+阈值），作用对象从"原始记录"换成"概念节点"；每一条关联额外生成：两个概念的"共同点"一句话总结 + 各自概念如何呼应这个共同点的一句话解释（供思维导图弹窗使用）
4. **图谱可视化，替换现有"关联主题"扁平列表**：
   - 力导向布局（节点间用真实物理模拟排布，不是人工摆位置）
   - 节点大小 = 这个概念挂载的划线/问答数量（触及越多越大）
   - 节点颜色按书本/思想流派分类分组（2-3个颜色，不要每本书一个颜色导致颜色噪音过多）
   - **孤立节点（没有检测出关联的概念）也必须显示**，不能因为没有连线就被过滤掉——用户需要看到"我学过但还没跟别的东西产生共鸣"的东西
   - **漂浮动效**：每个节点有轻微的独立漂浮动画，节奏各自错开（不能所有节点同步晃动，看起来要像自然漂浮不是机械抖动）
   - 深色"星空感"背景，整体极简，不用渐变/发光效果
   - **v1明确不做拖拽重新排列节点**——只支持点击，不支持拖拽（后续如果节点多到拥挤再评估要不要加）
5. **点击节点**：弹出浮层弹窗（半透明背景遮罩，图谱在背后隐约可见，不是整屏切换/跳转新页面），列出这个概念的所有来源（书名+段落片段+第2项生成的"为什么算这个概念"的一句话解释），弹窗有明确的关闭入口
6. **点击连线**：弹出浮层弹窗，用思维导图式的收敛排版——共同点标签在上方，两个概念各自的卡片在下方分别列出"如何呼应共同点"的解释+来源引用，弹窗有明确的关闭入口

### 质量门槛

- 图谱首屏加载 3秒内（跟阶段五复盘页同等门槛）
- 概念提取/关联解释的质量判断，人工抽查真实案例，不建自动化裁判（这类主观质量判断此前已经验证过LLM当裁判不可靠，参照苏格拉底提示词那次的教训）

### 明确不在本阶段范围内（不要默认展开）

- 拖拽重新排列节点
- 技能树式解锁效果（虚线/半透明表示"可以学习但还没学"）
- 链接预测式的学习路径推荐
- 提取"用户自己的理解方式"而不是标准概念术语
- 文言文词汇掌握度追踪
- 卡片式阅读
