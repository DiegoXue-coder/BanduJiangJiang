# 设计稿说明

这个文件夹存放决策层用HTML/CSS做的界面设计参考稿。**这些是给工程师实现时对照的精确规格，不是随便看看的效果图**——文件里的颜色值、间距、字号、组件位置都是决策层已经反复调整确认过的最终结果，实现时以这份文件里的实际CSS数值为准，不要凭文字描述重新诠释。

## 使用方式

1. 直接用文本工具打开HTML文件读源码——颜色（`--ember`这类CSS变量）、间距（px数值）、组件结构（哪个按钮在哪个位置）都写在里面，比任何文字转述都准确
2. HTML/CSS转React Native StyleSheet时遇到语法不对应的地方（比如CSS的`box-shadow`要换成RN的`shadow*`系列属性），按最接近的视觉效果实现，具体转换方式不确定的地方，问决策层或者用户，不要自己猜
3. **设计稿只覆盖它明确画出来的那些状态和元素**——没有出现在设计稿里的交互细节（比如新功能的手势、没画过的新增元素），设计稿不覆盖，需要另外找决策层要行为规格说明，不要照着设计稿去发明设计稿里没有的东西
4. 实现完第一版之后，把实际效果（截图或者详细描述）反馈给决策层核对，不要默认"照着做了就等于做对了"——这是复核关卡，不是走过场

## 当前文件

- `听书界面-设计稿.html`——阶段十七听书界面的视觉设计参考（2026-08-09定稿），暖色调+精密感细节（灯芯轨迹环、光尘漂浮、等宽字体状态标签）。**只覆盖"朗读中"和"打断·对话中"这两个视觉状态**，不包含进度条拖动、播放位置持久化、系统媒体控制面板——这几项是这份设计稿之后新增的需求，没有对应的视觉稿，需要按文字规格实现，参照设计稿的整体视觉语言（配色、字体、圆角/间距节奏）自行延伸，但具体布局设计稿没有画出来的部分不算有精确规格可循。
