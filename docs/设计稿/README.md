# 设计稿说明

这个文件夹存放决策层用HTML/CSS做的界面设计参考稿。**这些是给工程师实现时对照的精确规格，不是随便看看的效果图**——文件里的颜色值、间距、字号、组件位置都是决策层已经反复调整确认过的最终结果，实现时以这份文件里的实际CSS数值为准，不要凭文字描述重新诠释。

## 使用方式

1. 直接用文本工具打开HTML文件读源码——颜色（`--ember`这类CSS变量）、间距（px数值）、组件结构（哪个按钮在哪个位置）都写在里面，比任何文字转述都准确
2. HTML/CSS转React Native StyleSheet时遇到语法不对应的地方（比如CSS的`box-shadow`要换成RN的`shadow*`系列属性），按最接近的视觉效果实现，具体转换方式不确定的地方，问决策层或者用户，不要自己猜
3. **设计稿只覆盖它明确画出来的那些状态和元素**——没有出现在设计稿里的交互细节（比如新功能的手势、没画过的新增元素），设计稿不覆盖，需要另外找决策层要行为规格说明，不要照着设计稿去发明设计稿里没有的东西
4. 实现完第一版之后，把实际效果（截图或者详细描述）反馈给决策层核对，不要默认"照着做了就等于做对了"——这是复核关卡，不是走过场

## 已知的翻译难点（RN实现时会真的撞上，提前列出来）

- **CSS的`mask-image`渐变（网格背景淡出效果）**——RN没有直接对应的属性，需要用`MaskedView`这类库，或者用一层带透明度渐变的`View`叠加在网格上方模拟同样的视觉效果，两种做法选哪个、效果差多少，实现时自己判断，拿不准问决策层
- **3D coverflow的`rotateY`+`perspective`**——原型里用CSS `transform`跟着滚动位置实时插值，RN对应的思路是`Animated.ScrollView`配合`interpolate`按滚动偏移量算每张封面的`rotateY`/`scale`，1号之前做"未来感设计稿"那版书架时已经踩过一次这个坑（`react-native-svg`的Mask坐标系问题、coverflow居中计算错误），实现这版之前建议先翻一下之前那次的记录，不用重新踩一遍
- **底部弹出的sheet（问AI面板、导入提示）**——原型用CSS `transform:translateY`做滑入滑出，RN对应`Animated.Value`驱动`translateY`，或者直接用现成的bottom sheet库，两种都行，自己权衡要不要多引入一个依赖
- **日间/护眼/夜间三档色彩切换**——这个原型里是纯CSS变量切换，RN这边理论上应该复用`theme.js`已经有的light/dark两套token机制，新增"护眼"作为第三套token，不是从零发明新机制

## 实现优先级建议（不是必须严格按这个顺序，但这样返工风险最低）

1. `theme.js`换成雾灰蓝配色（含新增的护眼档）——全局改动，牵动所有屏幕，先做完这步再做别的
2. 书架首页——网格背景、分区、3D coverflow、导入按钮+格式提示面板、已读完徽章
3. 阅读器——顶部字体/日夜切换、右下角悬浮球、选中文字弹划线/问AI气泡、问AI底部面板
4. 听书页——麦克风开关（含斜杠表示关闭状态）、打断按钮、对话视图切换
5. 复盘+知识图谱——复盘列表、复盘详情、独立的知识图谱全屏页
